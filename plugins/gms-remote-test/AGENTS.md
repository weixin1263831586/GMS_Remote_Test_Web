# gms-remote-test plugin — agent maintenance contract

This directory is a self-contained kkagent MCP plugin. Read this file before
changing anything here.

## Layout

| Path | Role |
|---|---|
| `kk.plugin.json` | kkagent Plugin manifest; bump `version` when exposed tool behavior changes. |
| `kimi.plugin.json` | Kimi plugin manifest (same payload, adds `"skills": "./skills/"`). Keep `version` in lockstep. |
| `.codex-plugin/plugin.json` | Codex native plugin manifest (same payload). Keep `version` in lockstep. |
| `skills/` | **Copy** of `skills/gms-remote-test/` (SKILL.md + references + agents). Generated by sync; never edit here. |
| `scripts/mcp_server.py` | stdio MCP adapter. Tool schemas, envelope compaction, security gate. **Copy** — edit the skill source. |
| `scripts/gms-remote-test.sh` | **Copy** of `skills/gms-remote-test/scripts/gms-remote-test.sh`. Never edit here. |
| `scripts/sync_package.sh` | Syncs the CLI, MCP adapter and Skill payload from the skill source into this plugin, then validates the four-way version contract. |
| `scripts/install_local.sh` | One-command install/upgrade into `~/.kkagent/plugins/local/gms-remote-test` and registry sync. |
| `tests/test_mcp_server.py` | Offline unit tests (stub CLI, no Controller needed). |
| `tests/test_packaging.py` | Plugin self-containment tests: skill copy present, three manifests consistent, no `authorized=true` anywhere. |

## Change flow (mandatory order)

1. Edit the CLI / MCP adapter / SKILL in `skills/gms-remote-test/` — never in
   this copy.
2. `bash scripts/sync_package.sh`
3. `python3 tests/test_mcp_server.py && python3 tests/test_packaging.py` —
   must pass before shipping.
4. Adapter changes: keep every existing tool name and argument contract
   (API compatibility); add tests for new behavior.
5. Bump `version` in `kk.plugin.json`, `kimi.plugin.json` and
   `.codex-plugin/plugin.json`, plus `SERVER_VERSION` in the skill-source
   `scripts/mcp_server.py` and `GMS_RT_VERSION` in the skill-source CLI —
   `sync_package.sh` enforces the four-way contract.
6. `bash scripts/install_local.sh` to activate locally; restart kkagent.

## Security boundary (do not weaken)

- `gms_rt_run` executes only commands the CLI catalog marks
  `agent_safe_unattended` (read-only). Mutating/elevated commands are denied.
- `gms-rt-terminal-open`, `gms-rt-terminal-push`, `gms-rt-devices-scrcpy`
  are denied outright (`_DENIED_COMMANDS`).
- **Agent context never handles platform or admin passwords.** Agents
  authenticate with an Agent Service Token (`GMS_AUTH_TOKEN_FILE`, 0600).
  The password-based `gms_rt_auth_login` / `gms_rt_auth_elevate` tools are
  for a human session only and are not registered when the MCP server runs
  in service-token mode (`GMS_AGENT_AUTH_MODE=service-token`, set by the
  installer). Never document, suggest, or re-implement password login for
  an agent context.
- `gms_rt_burn_firmware` (added v0.6.0) is the only typed path to a
  mutating burn: it requires a one-shot server-issued approval token
  (hint on denial points agents to `gms_rt_approval_create`, which must be
  run by the user in their own human session) and forwards to
  `gms-rt-burn-firmware` with explicit wipe/wait-online arguments.
- `gms_rt_logcat` (added v0.7.0) is the typed path to
  `gms-rt-devices-logcat` (`adb shell logcat -v time`): it always runs
  dump-mode and rejects `-c/-f` and shell metacharacters. Clearing the log
  buffer (`logcat -c`) destroys diagnostic evidence and stays human-only
  via the CLI; the tool denies `clear=true` and raw `-c` in args alike
  (R17, 10.txt §六). The CLI catalog marks the raw command manual, so
  `gms_rt_run` cannot reach it.
- `gms_rt_shell_exec` (added v0.8.0) is the only agent path to
  `gms-rt-devices-shell`: it requires a server-issued one-shot
  `approval_token` (minted by the user via `gms_rt_approval_create`,
  bound to tool + device + SHA256(command), 5-minute TTL, single use) on
  every call. A client-declared `authorized=true` boolean was never a
  security boundary and is no longer accepted anywhere in this plugin —
  do not reintroduce it in docs, tests, or code. The bare/empty
  interactive shell stays human-only, `gms_rt_run` keeps denying the raw
  command, and the denial message points agents here.

## Token discipline (regression-test any output change)

1. `--json --non-interactive` injected into every subprocess.
2. Envelope compaction: drop `command`/`exit_code:0`, prune empty data
   fields, add exit-code `hint` on errors.
3. Catalog cached per process (5 min TTL); `gms_rt_commands` renders one
   line per command and omits `<name> [arguments]` fallback usage.
4. `gms_rt_run("system-docs")` renders one line per endpoint (~24KB → ~4.5KB).
5. `gms_rt_jobs_list` renders one line per job and `gms_rt_jobs_status` /
   `gms_rt_jobs_wait` trim the single-job payload (v0.6.0; ~60-80% smaller
   on real payloads). Error envelopes are never re-rendered.
6. Typed tools for hot paths so agents skip describe+run round trips.
