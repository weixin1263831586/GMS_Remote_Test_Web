接入链路分层

Source 侧（Windows / Linux）

usbipd-win 或 Linux usbipd 把本机 USB 设备以 USB/IP 协议暴露在 TCP 3240；设备仍物理插在 Source 主机。

Worker 侧（usbip attach）

Worker attach 远端共享后通过 vhci_hcd 得到虚拟 USB 总线；设备物理上始终连接 Source。ADB / Fastboot / Tradefed 在 Worker 侧使用对应设备。

Controller 协调

跨主机动作只经受审计 SSH 边界（ADR 0004）；USB/IP 设备的整包烧写不跨链路维持重枚举，按 ADR 0005 把设备所有权交还 Source Host 执行，期间暂停通用重连 watchdog。

USB/IP 链路无法跨越 ADB → Loader → ADB 的多次 USB 重枚举：断开即设备离线，Worker 以清单与心跳上报实际状态，Controller 不假设远端设备仍然存在。

AOA 恢复与回放拓扑

{{AOA_TOPOLOGY}}

执行链路分层

AOA 工作台（Web）

录制 / 回放 / 标定 Profile；Profile 按 owner 隔离存储，回放过程支持暂停 / 继续 / 终止（control_id 语义）。

Worker 回放

run_aoa_sequence 按物理 USB 端口绑定执行 AOAv2 控制：启动 Accessory，注入 HID 触点 / 按键序列驱动开机向导。

ADB 就绪判定

回放结束 ≠ ADB 已恢复：Worker 对 device 态做 adb shell true 往返校验，unauthorized 需要人工在设备上确认授权弹窗。

AOA 执行成功与 ADB 恢复是两个独立事实；结果里如实带回 adb_state，由调用方决定后续动作。

烧写链路分层

Web 烧写入口

固件分片上传与断点续传；烧写入口按设备所在 Worker 解析，跨 Worker 入口 fail closed。

Worker 烧写执行

本地 USB 设备由 Worker 接收类型化命令执行 upgrade_tool / fastboot；设备在 Loader / Rockusb 重枚举，成功后重启。

AOA 恢复接续（可选）

烧写成功与 ADB 就绪分离上报：可接续 AOA 恢复旅程（向导 → USB 调试），失败时提示单独调试而无需重新烧写。

完整固件烧写与 ADB 恢复是两个独立阶段。USB/IP 来源设备必须先暂停重连、detach 并复核所有权交还；Windows Source Agent 执行 RKDevTool 文件队列。Linux USB Source 的整包固件烧写尚未实现，直接拒绝（fail closed，ADR 0005）。恢复判定以 adb liveness 为准。

关键执行边界

01 · 接入与预检

权限、设备归属、Claim / Lease、Worker 可用性和测试套件检查；不可用时拒绝执行而不是盲目选择设备。

02 · 异步执行

Controller 持久化任务并入队；Worker 主动 Poll、ACK，在本地运行 Tradefed 并回报状态。

03 · 结果归属

原始 results / logs 来自 Worker 套件目录；报告管理只呈现 Controller 已登记的报告。

04 · 分析与重试

诊断、知识检索和 Redmine 反馈可按需接续。Worker 失联触发状态回收，不代表测试可跨主机自动续跑。

任务状态与安全约束

模型规划

kkagent 输出受控工具调用；不直接使用未知 Shell、设备凭据或绕过审批调用 Worker。

属主隔离

按用户配置的 Redmine 校验工单引用；同一会话运行中禁止重复入队，返回唯一 run_id。

状态跟踪

pending → snapshotting / analyzing → completed / partial / failed / cancelled，监控结果回传原会话。

报告回送

仅消费本次运行结果，不用历史报告冒充当前结论。取消 Agent 跟踪不等于取消 Redmine 后台分析任务。

模型分析提供诊断建议，不能替代 Controller 的资源授权、证据边界或真实工具执行回执。
