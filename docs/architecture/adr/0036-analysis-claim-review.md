# ADR-0036：单工单分析发布前逐段复核结论

- 状态：已采纳（Accepted）
- 关联：ADR 0013、0034、0035

## 背景

工单 #661066 的分析已读到原始大日志，但仍把进程内存分配失败升级成上游
测试缺陷，混用了 native 模块与另一个模块的 JAR，并误述了代码条件分支。
此前门禁主要验证取证工具调用、附件覆盖和引用存在性；总结模式还不检查
结论条目。调用成功与可复现源码数量不能证明最终文字准确。

## 决策

1. 模块查询保留完整标识符。精确模块只有 native/config 产物时，APK 解析
   返回没有适用工件，禁止自动替换成近似名称模块的 APK/JAR。
2. 源码取证轨迹保存结构化模块、任务、工件和套件版本元数据。文件名搜索、
   空正文和其他模块的内容不能满足当前模块的源码门禁。搜索用于定位；
   确认测试根因或责任方需要相关、可复现的正文读取，并匹配报障套件版本
   或已绑定的报障源码 revision。Controller 未掌握目标版本/revision 时，
   模型在复核 JSON 中自报版本不能替代它，只能保留推断。
3. 对话总结和页面诊断在发布前都追加一次原会话复核。模型重新检查每段
   正文，覆盖事实、机制、因果、责任和建议；重点核对条件分支、版本范围、
   时间相关性、负面证据与命令/选项。复核可补做原生只读取证。
4. Controller 提供完整正文段落与证据账本，以 SHA-256 绑定候选报告；要求
   复核返回所有段落的结构化判断。缺段、重复段、错误摘要、虚构/失败引用、
   无相关匹配版本源码却确认责任方、矛盾或待纠正内容均不得通过。
5. 不通过时沿用同会话补证据/修正文，再复核新正文。复核失败、超时或返回
   其他 session 时不得发布；修复次数耗尽后任务明确失败，不回退到旧结论。
6. 确实尝试源码取证后，允许通过复核的保守结果明确说明根因/责任待定。
   `source_evidence_checked` 仍为 false，并单独记录
   `source_limitation_acknowledged`；只有 Controller 校验后的复核记录可以
   开启该路径，模型自报的同名字段无效。其他取证门禁保持必需。
7. 修复提示允许修改原先错误的归因，不要求保留早期定论。完整证据引用
   索引不按 6000 字符或每条六个引用裁掉关键证据。
8. 最终展示仍是 kkagent 自己的总结/Markdown。复核 JSON 不作为答复，亦不
   引入固定的对话报告章节；以 `analysis_review` 和 `claims` 保存复核记录。
   取证调用不再自动提升到 0.85 或“证据已验证”；完成的模型复核仍标为
   部分闭环，因果/责任判断及不确定项保持人工复核标记。

## 边界与验证

复核使用原会话及原权限，属于额外模型检查，**不是独立模型或事实真值
证明**。Controller 能验证覆盖、身份、引用及部分来源约束，不能确定所有
自然语言推论。模型可能重复原有盲点，高影响定责仍需工程验证。

测试覆盖 native 模块误解析、无关 JAR、空正文/文件名命中、跨版本确认、
错误代码分支的复核拒绝、报告摘要/段落/引用篡改、修正后重新复核、连续
拒绝时禁止发布，以及上下文恢复/取消/原会话边界。真实工单重跑与设备复现
单独验收，单元测试通过不代表该工单根因已确认。
