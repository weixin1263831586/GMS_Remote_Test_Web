# ADR 0028：AOA 固件绑定恢复与严格环境验证

- Status: Accepted
- Date: 2026-11-05
- Supplements: [ADR 0027](0027-aoa-validated-mapping-boundaries.md)
- 部分后继：[ADR 0029](0029-aoa-class-certification-and-semantic-playback.md) 增加有实际参考回执约束的标准 direct 语义路径；下文记录本 ADR 作出时的约束。

## Context

数学验证通过不能证明未知设备环境兼容，刷机前的环境也不能证明刷机后的固件
兼容。开关和确认框等固定坐标操作需要明确的适用环境，不能静默换用估算映射。

## Decision

1. 人工工作台的估算调试语义保留。无人值守触摸恢复及烧写后自动触摸恢复必须有
   已验证源/目标映射，禁止 `estimated`、`direct_unverified` 和 `unsupported`。
   纯键盘、系统键、等待命令不因没有触摸标定而被禁止。
2. `/recover` 的目标环境只读取指定 Worker、指定设备的清单。请求中的
   `device_context` 不参与兼容性选择，源 Profile 不能充当目标环境证据。
3. 型号、版本、指纹、密度、分辨率、旋转、输入模式、内核和显示路由必须明确。
   双方均缺失、空值或 unknown 不能证明相同。历史不完整记录不再自动复用；
   新保存记录也必须完整。数学拟合工具仍可以分析缺少上下文的样本。
4. Profile metadata 中的 `firmware_compatibility` 是账号负责人提供的明确实测
   声明，绑定单个固件 SHA-256、完整目标固件环境、验证人、带时区的验证时间及
   实测证据引用。它不自动生成，不是设备类别认证，不能提升为 `direct_standard`。
   刷前设备清单仅用于核对目标型号和物理 USB 身份；匹配矩阵使用声明的刷后环境。
5. 自动化在预约前冻结声明和映射，恢复/烧写前再次验证。Controller 暂存计算真实
   镜像摘要，不匹配不创建烧写命令；Worker 下载校验后、烧写前再核对。Controller
   本机烧写也核对实际执行主机上的镜像摘要，拒绝不匹配，沿用原占用清理流程。
6. 自动坐标重投影严格检查源显示区域及目标 HID 可达范围；超界抛错，不吸附边缘。
   点击和滑动两个端点均校验。仿射变换和矩形区域的凸性保证端点合法的滑动线段
   也位于可达区域。保留人工坐标检查的显式非严格接口。
7. 标定 Activity 启动后、USB 重枚举后每次探针 DOWN 前，检查目标显示器、当前
   焦点和锁屏状态。未知焦点、其他窗口覆盖或显示器不符时停止；尚未建立 USB
   会话时不执行 USB 清理写入。远端标定需要 `aoa_calibration_focus_v1` 能力。

## Verification

测试覆盖两种估算策略禁止进入无人值守恢复、伪造请求上下文、双方缺失环境字段、
刷前与刷后指纹不同、实际固件摘要不符时无烧写命令/无残留占用、源/目标越界、
锁屏/弹框/显示器变化及不确定焦点下没有探针 DOWN。实机 HID 分类、落点、显示
绑定和完整开机向导仍需硬件验收。当前没有已认证设备类别，`direct_standard` 继续拒绝。

## Revision 1（2026-11-05）：声明与标定闸门降级为选择性强化

实机使用表明"无声明即拒绝"阻碍了日常烧写（声明要求实测固件 SHA-256，而摘要
只能在暂存时由 Controller 计算，形成先有鸡还是先有蛋的死锁）。修订如下：

- 未填写 `firmware_compatibility` 的 Profile 预检与烧写**放行**：无人值守触摸
  恢复按未验证映射（`estimated` / `direct_unverified`）执行，Worker 端结果如实
  标注 `mapping_policy` 与 `touch_mapping_verified`，不视为已验证坐标。
- 一旦填写了声明，仍按本 ADR 原则严格校验全部字段并随快照冻结绑定；冻结后的
  声明不得移除或篡改（快照一致性检测保留）。
- 声明存在时，已验证源/目标映射强制要求恢复（Decision 1 不变）；声明缺失时
  该强制要求同样暂停，估算映射允许进入无人值守回放。
- 语义回放的冻结环境绑定仅在声明存在时执行；无声明时语义回放仍需有效参考
  回执约束（ADR 0029），但不做固件环境等值断言。
- Worker / Controller / 暂存各处的 `require_firmware_digest` 实际镜像摘要核对
  保持不变：有声明就必须匹配实际镜像。

## Revision 2（2026-11-05）：刷机后 usb_only 阶段的环境信任模型与语义单步语义

本文后续修订：发现两类恢复阻断与字段混用，修订如下：

- **刷机后清单不再要求 ADB-only 属性。** ADB 关闭后 Worker 只能上报
  `usb_only`（usb、VID/PID、序列号），而认证语义计划的环境（`model` /
  `board` / `hardware`）只能来自刷机前经 ADB 冻结的 `aoa_context`。
  自动化语义恢复的授权改为：同一 `automation_run_id` 的**成功烧写回执**
  （`flash_firmware` `payload.sha256`）+ 冻结认证计划 + 物理身份链路
  （serial/冻结 USB 端口/租约/Worker 端 `validate_binding`）构成恢复证明；
  清单仍在场报告的键（如异常重枚举后重新可读的属性）必须与冻结计划一致，
  冲突仍拒绝——保持安全边界，不跳过校验。
- **实际镜像摘要与固件声明分离。** 烧写回执的 `payload.sha256` 是权威绑定；
  `firmware_compatibility` 声明是可选的事前证据。声明存在时必须与回执摘要
  一致；无声明时回执本身即绑定，不再要求 `aoa_firmware_sha256` 预先存在。
- **语义单步调试允许 `wait_adb_seconds=0`。** 单步成功由该步骤的 before/
  after 画面断言与 USB 清理结果决定，不以"ADB 恢复"为验收前置；完整恢复
  回放仍保留 ADB 最终验收。普通回放入口维持"至少等待 1 秒"的既有语义。
