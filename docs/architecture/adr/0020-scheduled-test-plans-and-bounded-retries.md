# 0020. 人类预授权的测试计划与有界失败用例重试

- 状态：Accepted
- 日期：2026-10-31
- 补充：ADR 0012 的运行派生边界；ADR 0004 的 SSH 执行边界保持不变。

## 背景

GMS 需要持久化的定时、多套件顺序测试，以及已失败用例的有界自动重试。
这些操作会在未来创建运行，必须区别人类的预授权与机器自行增加执行权限。

## 决策

1. 计划创建、更新、启停和执行入口均为 human-only 且按账号隔离。管理员也不能
   替其他账号修改计划。Agent 和机器身份不能通过 HTTP 创建计划或派生运行。
2. 人类保存计划时，使用现有 `prepare_run` 和 `automation_granted_capabilities`
   验证每步配置与权限。运行模板及凭据作为加密的操作快照保存在 automation
   数据库中；列表、执行历史和错误消息不返回模板或凭据。
3. 每次新步骤派发及自动重试前，重新解析启用的创建者账号，校验账号 ID 与
   当前能力，同时要求所需能力属于保存的快照。账号删除、禁用、改名或权限
   撤销会阻止新的工作；角色提升不会扩大已保存的权限。
4. 定时仅支持手动、间隔、每日、每周。每日/每周使用显式 IANA 时区；夏令时
   缺失时刻跳过，重复时刻只取第一次。恢复后不补跑全部历史周期；有未结束
   批次时跳过本次定时，保持同一计划不重叠。
5. 计划版本、批次、下一步骤及派生运行保存在同一个 SQLite 数据库中。
   `BEGIN IMMEDIATE` 事务同时提交派发记录、运行、凭据与创建事件；并发进程
   或重启不能重复派发同一步骤或同一轮重试。迁移沿用持有写锁的幂等建表方案。
6. 自动重试必须由人类在运行配置中明确开启，上限 0–5 次，间隔 10–3600 秒。
   只处理执行完成、摘要明确失败、且存在精确归档报告及原 Worker/结果目录
   上下文的运行。未知结果、基础设施错误和取消不触发自动重试。
7. 重试在同一 Worker/套件上以现有 `retry_dir` 结构化执行，只重试失败用例；
   移除构建及模块/用例选择，烧写显式跳过。权限快照不增加；新运行不继承
   租约或结果，保存根运行、直接来源、轮次及最早执行时间。执行仍经原有
   audited SSH 通道，Worker→Controller 汇报仍使用认证 HTTP(S)。
8. 多步骤计划等待当前步骤及其有界重试结束。失败或未知结果可配置停止后续；
   选择继续时保留批次中的最终步骤失败事实。“停止后续”阻止新步骤和重试，
   不取消已经启动的测试，直到其终态才解除计划的批次占用。暂停定时和取消
   一个具体运行保持独立语义。

## 验证

`test_planning.py` 覆盖并发派发、重启恢复、时区/DST、跳过重叠周期、重试上限、
精确上下文、权限撤销与停止后续；`test_plan_api.py` 覆盖所有者、机器拒绝、
版本冲突和凭据遮蔽。浏览器测试验证草稿、多步骤保存、调度编辑与初始化只读。
