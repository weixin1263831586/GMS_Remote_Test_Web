# ADR 0027：AOA 映射验证与跨边界传递

- Status: Accepted
- Date: 2026-11-04
- Supersedes: [ADR 0026](0026-aoa-multi-point-affine-calibration-and-mapping-policy.md) 的验证、策略提升与降级规则

## Decision

1. 五个点用于拟合，额外两个不同的点仅用于独立验证。反序列化时检查
   可逆性、有限值、采样范围、环境一致性，并由样本重新计算误差；旧记录
   缺少独立验证时不能自动复用。安全标定应用启动失败时不发送探针；失败
   不再降级为在普通页面进行单点探测。
2. direct 仿射修正称为 `direct_calibrated`。误差达标不证明输入设备分类、
   内核轴范围或显示绑定正确，不能自动提升为 `direct_standard`。当前拒绝
   从普通 Profile/标定 API 声明 `direct_standard`，设备类别认证和真机证据
   是后续独立验收项。此变更不宣称已实现通用免逐台标定。
3. 相对位置转换为：源 HID → 源像素 → 按目标/源宽高归一化 → 目标映射逆变换。
   源/目标旋转不同时拒绝转换，UI 布局适配仍由操作模板负责。
4. `ClusterDeviceAction` 显式声明源映射、目标映射和策略，校验类型、模式、
   策略一致性及 64KiB 上限。连续、按单条和持久调试均只转换一次；调试会话
   固定映射参数。`unsupported` 对触摸指令始终生效，不影响纯键盘/等待命令。
5. 目标环境来自目标 Worker 的只读清单，不能用源 Profile 补齐未知目标。
   匹配包含型号、Android 版本、指纹、密度、分辨率、旋转、HID 模式、内核和
   显示路由。缺失已保存的环境信息也视为不匹配。无法核对的已标定触摸回放
   在派发前拒绝。无标定的旧模板保留明确的 estimated/unverified 手动回放语义。
6. 烧写前按真实目标环境冻结映射；本机和远程 Worker 使用相同映射参数。
   自动化运行也在预约前冻结源/目标映射，并在烧写前检查 Worker 标定协议能力；
   携带源标定但缺少映射快照的旧运行需要重新创建。
   烧写后无需查询 ADB 元数据才能发送已冻结命令，最终成功仍要求
   `adb_recovered=true`。新固件改变布局/映射的兼容性须事先验证。
7. 标定保存显示结果与记录 ID；失败明确提示。数据库保存完整映射并按账号
   隔离；无效历史记录不再自动复用。

## Verification

测试包含不同分辨率中心保持、保存后重查、真实请求模型到持久回执的映射传递、
三种回放模式实际发出的 HID 坐标、奇异矩阵、伪造误差、独立点失败、策略禁用、
目标环境不匹配和无 ADB 元数据查询的烧写恢复。硬件分类、显示路由、实际落点
以及安全标定 APK 的设备验收独立于这些软件测试。
