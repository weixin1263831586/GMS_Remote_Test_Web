# ADR-0037：最新报告查询覆盖原生套件结果

- 状态：已采纳（Accepted）
- 关联：ADR 0001、0010、0031

## 背景

“最新 GTS 测试报告”曾只读取当前账号登记库前十项，并忽略测试类型和
工作区 Worker。登记库为空时，实际存在的 `android-gts/results/<run>/`
结果未被查询，却得出了“没有 GTS 报告”的结论。

## 决策

1. 对话工具 `reports_list` 明确提供 `test_type`、`latest`、`limit` 和
   Worker 参数；用户明确的测试类型及最新查询约束由 Controller 保留。
2. 登记报告复用报告 API 的权限、账号/管理员范围、Worker 筛选和分页。
   最新查询读取全部分页，比较测试时间，不能把上传时间或前十项当成最新。
3. 最新查询同时读取可访问 Worker 的所有匹配套件版本。原生摘要通过
   `suite_action/report_summaries` 的既有认证命令边界执行；不增加 Controller
   任意文件读取、原始 SSH 或绕过 Worker ACL 的通道。
4. Worker 在配置套件根内逐个检查原生结果 XML 的 Result/Summary 元数据，
   流式读取直到取得摘要，禁止 DTD/实体及路径逃逸。每个结果都参与扫描，
   不按文件大小或目录数量整份跳过；比较实际测试时间后再限制返回数量。
   摘要不声称完成失败用例或整份 XML 的内容分析。
5. 任一来源失败、摘要不可读或测试时间无法比较，都保留覆盖缺口；已有
   候选可返回，但 `latest_confirmed=false`。失败不能伪装成零报告。
6. 原生目录没有账号、Job 或 ATS run 归属，因此显式个人/运行范围查询仅
   使用有对应归属的登记记录。返回值区分登记来源、原生来源及查询范围，
   不把 Worker 可读权限等同于账号所有权，也不自动导入或修改原生报告。
7. 查看能力由 Controller 根据登记/原生来源绑定到 `access.open_action`。
   未登记原生结果使用携带 Worker、套件和目录的测试套件浏览入口，不显示
   报告管理入口、不生成猜测的 HTML API、不作为已保存报告实体传给后续
   分析。最终回复附上实际入口按钮；摘要不等于已读取失败用例明细。

## 验证

回归覆盖空登记库命中原生结果、跨版本比较、超过一页的登记记录、类型/
Worker/账号筛选、权限及 Worker 故障、损坏/大 XML、实体和路径逃逸。
真实目录验收覆盖本机两个 GTS 套件共 176 份结果，按 XML 开始时间得到
`android-gts-14-R4/android-gts/results/2026.11.13_14.22.45.723_8397`。

上线需要 Controller 和承载该动作的 Worker 使用包含此动作的代码；旧
Worker 不支持该动作时，查询保留明确缺口，不退回“暂无报告”。
