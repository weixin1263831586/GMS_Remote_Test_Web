# AOA 回放命令轨道与过程控制

完整协议原理、架构、录制实现及故障判断见
[AOA 工作台：原理、实现与系统架构](aoa-mechanism-and-architecture.md)。

点击“开始回放”后，当前列表属于所选配置时采用列表中的编辑内容，否则读取
该配置的命令。右侧“UI 操作对应命令”展示本次回放的完整命令
快照；请求发送同一份命令，避免页面加载后 Profile 修改造成显示与执行不一致。

每条命令显示序号、内容和状态：待执行、执行中、已完成、已暂停或失败。
执行器在命令开始前上报当前步骤，完成后上报完成状态；页面每 500ms 增量
读取进度并在命令列表内部定位当前行。事件序号独立于步骤序号，同一步的
暂停、继续、开始、完成事件不会被数据库去重丢弃。

暂停/继续/停止按钮位于命令轨道标题行（仅回放期间显示），回放进度与
单条调试状态显示在右上角运行状态胶囊；「保持连接」「结束调试」位于命令列表
表头右侧；导入、导出与撤销、清空同排：

- 暂停在当前完整命令结束后生效，不截断按下/抬起或滑动。确认暂停后显示
  下一条待执行命令；继续从该命令执行，不重新派发整个序列。
- 按钮先显示请求中，收到执行器确认后才切换到已暂停/继续状态。
- 暂停期间保留原设备租约并持续校验 fencing。累计暂停上限为 10 分钟，
  防止遗留操作长期占用设备；暂停时间不消耗原命令执行预算。
- 已执行命令不能撤回。停止会结束后续命令并执行 USB 清理。

控制请求必须匹配原命令的账号、Worker 和控制句柄，终态操作不能继续。
本机通过持久命令状态读取控制请求，支持 Web 多进程；远端通过原 Worker
命令通道传递带修订号的控制消息，迟到的暂停不能覆盖较新的继续。

远端 Worker 必须更新并声明 `aoa_playback_control_v1`。更新 Controller 与
Worker 后重新加载页面；已有旧执行器上的回放无法通过刷新页面获得新控制能力。

验证覆盖完整 100 条命令显示、逐步状态、暂停确认、继续且只派发一次、
跨账号/Worker 拒绝、同一步多事件、控制乱序、暂停预算及租约失效。
浏览器使用模拟接口，执行器使用 USB 桩；未执行真机输入或 USB reset。

## 管理员强制释放本机回放

设备管理中的“释放设备”需要管理员提权。针对独立的本机 AOA 回放，释放会先将
原命令置为取消并写入取消控制，再按原 lease ID 和 generation 原子撤销该操作的
设备锁与 USB 物理端口、传输别名锁。原执行器在下一次 fencing 检查时停止，迟到的
成功回执不能恢复已取消的回放；不会自动重新派发命令。

强制释放可能打断正在发送的输入，结果标记 `forced_release=true` 和
`reconcile_required=true`。应先确认设备当前界面，再手动决定后续操作。
正常测试任务、预约、借用的设备锁、正在烧写的任务及远端执行中的回放继续受保护；
这些占用需要先通过各自的停止或取消入口结束。已结束的独立设备操作可以清理残留锁，
并保留原命令的成功或失败结果。不能确认原命令、设备身份或租约时拒绝释放。

释放冲突返回 HTTP 409、`STATE_CONFLICT` 和具体原因，不再使用 HTTP 200 包装失败。

## 单条命令调试

每条命令右侧的“执行”按钮会在“目标设备回放”所选 Worker 和设备上，只执行
该条 AOA 命令。调试使用现有设备动作、租约和持久回执通道，不附加前后命令
或 ADB 恢复等待，适用于逐条检查点击、按键、滑动和等待命令。

执行期间该行显示“执行中”，全部执行/编辑按钮暂时禁用，完成后显示“已执行”
或具体失败原因。调试保留完整命令列表及其顺序。整段回放（含暂停状态）期间
禁用单条执行，避免与已持有 USB 通道的回放交叉输入。

每行的“编辑”打开命令输入框，点击“保存”或按 Enter 应用修改，点击“取消”
或按 Escape 放弃草稿。单条执行、回放、导出及保存配置前会先应用正在编辑
的内容；空命令会阻止这些操作。修改立即用于当前调试，点击“保存当前命令”
后才持久保存到配置。当前列表来自所选配置时，回放使用列表中的修改内容；
切换至其他配置则回放该配置的命令。执行及暂停期间禁止编辑。

未勾选“单条调试保持 HID 连接”时，每条调试都会进入 accessory 模式，结束后复位 USB 并恢复原生模式，因而
可能产生短暂断开/重连日志。需结合命令结果中的 `native_mode_restored`、
`cleanup_errors` 判断恢复状态；没有操作时仍持续重连或伴随失败不能视为正常。

勾选“单条调试保持 HID 连接”后，第一次执行按当前完整命令列表注册所需通道，
但只发送选中的一条命令。后续单条执行共用原 USB/HID 会话和设备锁，不反复移除
鼠标。兼容鼠标模式下，Mouse 条目会与整段连续回放一样持续存在，适合校准整段
脚本的坐标；首次建立连接较慢，后续执行省去连接与清理开销。

点击“结束调试”、离开 AOA 页签、空闲 2 分钟或会话累计满 15 分钟后，统一释放
输入、注销 HID、恢复原生 USB 并释放设备锁。仍在清理时继续跟随原回执；网络故障
不会自动重发输入。调试只支持本机 Worker，远端 Worker 请求明确拒绝。
会话期间可以编辑坐标和逐条执行；设备、输入模式与通道集合固定，需要新增 HID
通道时应先结束调试再执行。整段回放、探测、录制和标定须在结束调试后进行。

配置中的“回放方式”另可选择“按单条方式回放”：每个非 sleep 动作独立建立并清理
USB/HID，sleep 在原生 USB 状态下执行，速度较慢。默认连续回放保持原行为。
切换生命周期会改变 Mouse 条目存在的时机，须使用对应方式下验证的坐标；增加
sleep 只能等待布局稳定，不能隐藏仍已注册的鼠标设备。
