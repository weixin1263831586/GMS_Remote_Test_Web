# GMS更新雷达

入口：**常用工具 → 测试工具 → GMS更新雷达**。

卡片上的 **修改** 可直接打开设置弹框；进入雷达页面后，顶部的 **修改**
打开同一份配置。管理员可保存配置、启动扫描和重发邮件；已登录用户可查看
扫描历史及变更明细。

## 配置监听

1. 点击 **修改**，设置执行时间和时区。默认每天 **04:00，Asia/Shanghai**。
2. 选择监听任务。默认全部监听，也可仅勾选部分任务，至少保留一项：
   GMS要求、GMS包更新、Mainline包更新、测试套件更新、Critical_Patch、
   Mainline包豁免项。
3. 填写收件人，支持逗号、分号或换行分隔，最多 50 人。
4. 默认策略为 **仅有变更或扫描失败时发**。没有变化的扫描仍保留记录，
   邮件标记为“按策略未发送”。也可切换为每次扫描都发送。
5. 填写收件人可访问的雷达页面地址，用于邮件中的详情链接。
6. 勾选 **开启每日扫描** 并保存。未开启时仍可手动扫描当前选择的任务。

首次使用每日计划默认关闭，填写收件人后才能开启。SMTP 复用系统级配置，
请在 **测试执行 → 系统设置 → 邮件发送方** 配置发件账号并打开邮件总开关。
雷达不重复存储 SMTP 密码。后台任务由平台服务执行，关闭浏览器不会停止计划。
时区使用 IANA 名称：夏令时回拨出现重复小时，每个本地日期最多计划一次，
选择重复时刻时使用第一次出现的时间；春季跳时造成指定时刻不存在时，
按该时刻映射到跳时后的有效时间执行（例如 02:30 对应 03:30）。

修改监听任务不改变已产生的扫描记录：每次执行会保存当时的任务选择和
邮件配置。全量扫描表示重新抓取、解析所选项目，而非跳过内容未变化的页面。
Mainline包、豁免条目和安全补丁（CVE）使用相同发布文档，默认覆盖全部发现的历史发布页面。

## 查看结果

点击 **立即全量扫描** 执行所选任务，或等待计划到时运行。扫描历史分别展示
扫描状态、变化数量和邮件状态；**查看** 显示本次监听范围、扫描前后数量、
新增/修改/移除数量，以及逐条字段的扫描前后数据。

首次扫描也会先读取当前平台数据进行比较。只有原数据库为空时，才标记
“首次建立基线”，并将首次发现的数据记为新增。扫描时间、最后发现时间、
SQLite 行 ID 和内容哈希不作为业务变化。

“移除”表示条目不再出现在本次解析的数据中，不直接等同于上游撤回；
应结合原始链接和页面范围判断。变更统计保留在平台；单次每日扫描最多保存 2,000 条明细，周期快照最多保存
20,000 条明细，超限时保留总量并明确标记截断。HTML 邮件展示汇总和前
20 条面向阅读的变更摘要，长字段节选展示，已保存的字段证据可在网页中展开查看。
原纯文本摘要接口保留作为兼容数据，不直接充当 HTML 邮件正文。

每日雷达使用统一扫描批次的 `gms_update_change_events` 作为业务变化唯一来源，
只另行读取分类库存总量，不再对全量业务行独立计算差异。历史周期快照仍按已保存事件汇总。

## 每周与每月快照

开启每日扫描后，系统按配置时区在周一及每月 1 日的扫描时间到达后，自动
生成上一自然周（周一至周日）及上一自然月的快照；两种快照独立保存。
在「扫描历史与周期快照」中选择每日扫描、每周快照、每月快照或全部记录，
可查看对应记录、统计、变更明细及邮件。周期邮件不受每日「仅有变更或扫描失败时发」
策略限制，即使净变化为零也会发送。

快照汇总按扫描完成时间归入本地自然周期，同一类别、同一业务主键的连续变化
合并为周期首尾净变化；恢复原状的条目不计入净变化，但保留累计观察变更次数。
缺扫、失败、首次基线、证据不连续或明细截断会标记覆盖不完整，不能视为 Google
整个周期的全部更新。快照只汇总已记录的每日扫描，不额外抓取上游数据。

相同自然周或自然月仅生成一次；恢复服务后只处理最近已经结束的周期，不逐个补建
更早的历史周期。每日扫描记录至少保留最近 62 天且保留最近 200 条终态记录，
周期快照不受每日记录清理规则影响。

## 失败与恢复

- 所有任务使用统一扫描服务和 gms_update.sqlite3。按数据源事务发布，Mainline 部分覆盖时仅补录有证据的记录，不删除旧数据；失败不能认定无更新。
- Partner 页面继续使用平台现有登录凭据。后台扫描失败时不会自动弹出主机
  浏览器；重新登录 Partner 后可手动重扫。
- 卡片手动扫描与雷达使用同一运行状态互斥，雷达自身也只能有一轮扫描运行。
- 服务停机错过的计划，恢复后补跑一次并继续后续计划，不连续补发所有历史日期。
  开启计划时安排下一次未来执行；停用计划不取消已经运行的扫描。
- 重启时未完成的扫描标记为中断；已完成的扫描结果保留。重启前正在发信而
  无法确认投递结果时，标记“发送状态未确认”，不自动重发。
- SMTP 失败不删除扫描结果。修正 SMTP 或收件人后，在该批次 **重发本次汇总**，
  使用当前邮件设置发送原批次结果，不重新扫描。发送状态未确认时先核对邮件台账。
- **预览邮件** 只读取内容；发送尝试进入系统历史邮件台账，通道为 **GMS更新雷达**。
- 邮件正文使用 HTML 表格：扫描摘要、各监控项前后数量与增改删、失败组异常、最多
  20 条可读变更明细。新增用绿色、修改用琥珀色、移除用红色，失败和旧数据保留
  另行提示；0 变更且部分失败不得称为全量无更新。雷达页面保留完整原始字段供展开。
  所有外部扫描内容进行 HTML 转义，邮件预览不执行脚本。

后台计划、历史和字段差异保存在运行数据根下的 `gms_update_radar_v2.sqlite3`。
这些是部署运行数据，不进入代码仓库。架构取舍见
[ADR 0038](architecture/adr/0038-update-radar-scans-and-notifications.md)。

## Android API Level 与套件发布版本

Android 13～17 对应 API 33～37。套件发布号的小版本（如 `14.1`）并不是 API Level 的小数位；
版本元数据需分别保存，官方 CTS/VTS 章节链接按 Android 主版本定位。
